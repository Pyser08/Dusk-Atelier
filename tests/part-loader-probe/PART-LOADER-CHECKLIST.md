# Dusk Atelier 파츠 로더 검증 체크리스트

## 목적
RisuAI 공식 API로 가능한 범위를 실환경에서 확인한다. 이 도구는 **임시 진단용 플러그인**이며 제품 구조에 포함하지 않는다.

## 설치 전 주의
- [ ] 현재 Dusk Atelier를 백업하거나 원본 파일을 보관했다.
- [ ] 진단용 플러그인 `Dusk Atelier Part Probe`는 테스트 후 제거할 예정임을 확인했다.
- [ ] 테스트는 신뢰하는 저장소에서 받은 파일로만 진행한다.

## A. 기본 UI와 공식 API
- [ ] RisuAI 설정 → 플러그인에서 `Dusk Atelier Part Probe`를 임시 설치/활성화한다.
- [ ] 진단 화면을 연다.
- [ ] API 목록에서 `nativeFetch`, `pluginStorage.getItem/setItem`가 '있음'인지 확인한다.
- [ ] `loadPlugins`는 존재 여부만 확인한다. **누르거나 호출하지 않는다** (전체 플러그인 재로드 API).
- [ ] `loadExternalModule`, `importPlugin`가 없다고 표시되는지 확인한다. 이 이름들은 현재 공식 API에서 확인되지 않은 후보명이며, 존재하지 않는다고 해서 미래의 모든 방법까지 부정하는 것은 아니다.

## B. 외부 JSON 독립 갱신
- [ ] 'JSON 가져오기 + 캐시 저장'을 누른다.
- [ ] HTTP 요청 성공 및 `dataVersion: 1.0.0`, `REMOTE_DATA_V1`이 로그에 표시되는지 확인한다.
- [ ] '캐시 읽기'를 누르고 동일한 버전/메시지가 나오는지 확인한다.
- [ ] RisuAI를 새로고침한 뒤 다시 열고 '캐시 읽기'를 눌러 캐시가 유지되는지 확인한다.
- [ ] 이 테스트가 끝나면 ChatGPT에 결과를 알려준다. 원격 JSON을 V1.0.1로 바꿔줄 수 있으며, 그 뒤 플러그인 재설치 없이 새 버전이 읽히는지 2차 테스트한다.

## C. 외부 JavaScript 파일 다운로드
- [ ] 'JS 텍스트 가져오기'를 누른다.
- [ ] HTTP 성공, `markerFound: true`, `executionAttempted: false`가 표시되는지 확인한다.
- [ ] 이 테스트는 다운로드만 증명한다. **JavaScript를 실행하지 않으며, 실행 가능 여부를 증명하지 않는다.**
- [ ] 외부 JS를 `eval`, `new Function`, 동적 script, 샌드박스 우회로 실행하려고 시도하지 않는다.

## D. UI Ping 경로
- [ ] '로컬 파츠에 Ping 보내기'를 누른다.
- [ ] `PONG_FROM_EMBEDDED_PART`가 표시되는지 확인한다.
- [ ] 로그의 `source: same-bundle-stub`를 확인한다. 이것은 같은 번들 안 함수 호출의 기준선일 뿐, 외부 파츠 호출의 증거가 아니다.
- [ ] 테스트 플러그인이 RisuAI 플러그인 목록에 나타나는지 확인한다. 별도 플러그인 설치 방식은 사용자 목표인 '파츠 비노출'을 충족하지 못한다는 점을 기록한다.

## 현재 테스트의 한계
이 진단 도구는 공식 API만 사용한다. 외부 JS를 다운로드해 실행하는 기능, 플러그인 탭에서 파츠를 숨기는 기능, 특정 파츠의 실행 코드를 독립 업데이트하는 기능은 구현하거나 우회하지 않는다. 해당 기능을 뒷받침하는 공식 API가 확인되지 않았으므로, 먼저 지원되는 데이터/캐시/UI 신호 경로를 실환경에서 검증한다.
