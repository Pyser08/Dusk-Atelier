# 아카라이브 업데이트 글(HTML) 만들기

릴리스 안내글을 아카라이브(arca.live/b/characterai)에 올릴 HTML로 만드는 절차.
**사용자가 요청할 때만 만든다.** 버전 번호도 사용자가 알려 준 것만 쓴다(임의로 정하지 않음).

## 1. 준비
1. 사용자에게 확인: ① 글 버전 ② 이전 글 주소 목록(시리즈 박스용 — 모르는 글은 링크 없이 글자만) ③ 이번 글에 넣을 내용 범위.
2. 내용 출처는 **`CHANGELOG.md` 해당 버전 섹션과 `docs/GUIDE-v*.md`**. 여기 없는 기능은 쓰지 않는다(지어내기 금지). 애매하면 코드/테스트로 확인하거나 사용자에게 묻는다.
3. 형식 기준 파일: **`docs/arca/` 안에서 가장 최근 버전 HTML**(현재 `v1.8.1.html` — 2x2 요약 카드·기능별 파트·기능별 하이라이트 색(주황/분홍/초록/하늘) 기준)을 열어 구조·스타일을 그대로 따른다. 처음부터 새로 디자인하지 않는다.
4. 결과 파일: `docs/arca/v<버전>.html` (조각 HTML — `<html>`/`<body>` 없이 `<div>`로 시작). 사용자가 직접 넣겠다고 하면 파일만 만들어 전달한다.

## 2. 글 구조 (위에서 아래로)
1. **시리즈 박스**: "Dusk Atelier 시리즈 · 전체 N편 · 최신순". 이번 글은 강조 줄 + "지금 보는 글", 이전 글은 링크. N은 이전 편수 + 1.
2. **`<details>` 사용 가이드**("📖 처음이라면 — Dusk Atelier 사용 가이드"): 최신 글의 것을 그대로 옮긴다. 기능이 바뀐 부분(탭 이름 등)만 현재 화면에 맞게 수정.
3. **본문 큰 박스**: `border-radius:18px;background:#151326;border:1px solid #3b3659`, 맨 위 6px 그라데이션 줄.
   - 머리: `UPDATE · v버전` 배지, 26px 제목, 한 줄 소개, 이모지 기능 카드(`flex:1 1 140px`) 3~4개.
   - 항목: `margin:34px 26px 0`, 번호 원/사각 + 19px 제목, 본문 15px, 목록 `·` 14px, 강조 줄은 `#1b1930` 카드.
   - 경고 박스: 배경 `#2a2238`, 테두리 `#5a4470`, 글자 `#e8c9a6`.
   - **설치하기 박스**(가운데 정렬, 큰 다운로드 버튼): `https://github.com/Pyser08/Dusk-Atelier/releases/latest/download/dusk_atelier.js`
   - **🌊 RisuTide SPECIAL THANKS** 블록과 하단 "with RisuTide" 띠 — 최신 글의 것을 그대로 유지.
4. 길고 부차적인 내용(예제 코드, 상세 설명)은 항목 아래 `<details>`로 접는다.

## 3. 아카 에디터 제약 (어기면 화면이 깨진다)
- `<a>`의 `style`은 지워진다 → 링크 안에는 스타일을 준 `<span>` **하나만** 넣는다.
- `<a>` 안에 `<span>`을 여러 겹 넣지 않는다(안쪽이 지워짐). 줄 모양·배경은 링크 **밖** `<div>`가 맡는다.
- `overflow:hidden`은 무시된다 → 모서리 둥글기는 각 요소에 직접 준다.
- 스타일은 전부 **인라인**(`style="…"`). `<style>`·`class`·외부 CSS·스크립트 불가.
- 이미지는 사용자가 아카에 올린 뒤 얻은 주소를 쓴다. 이미지 주소를 지어내지 않는다 — 자리만 표시하고 사용자에게 요청.
- 색은 최신 글에서 쓰는 팔레트만(배경 `#151326`/`#1b1930`/`#221f3a`, 테두리 `#3b3659`, 글자 `#ecebf6`/`#c9c6e3`/`#9d99c1`, 강조 `#a891ff`·`#c4b1ff`, 그라데이션 `#4f7cf7→#7c5cf0`).

## 4. 문체
- 한국어 "~해요" 체, 짧은 문장. 과장·홍보 문구 금지, 사용자가 실제로 체감하는 변화 중심.
- 각 항목: 무엇이 바뀌었는지 → 왜 좋은지 → (필요하면) 쓰는 법 한 줄.
- 버그 수정은 "고친 점"으로 묶어 간단히.

## 5. 마무리 확인
- 시리즈 편수·"지금 보는 글" 위치, 이전 글 링크, 설치 링크, 버전 표기가 서로 맞는지.
- 3절 제약 위반 검사: `grep -n "<style\|class=\|<script\|overflow:hidden" 파일` 결과가 비어 있어야 함(이미지 태그의 `class`는 사용자가 붙여 넣은 아카 원본이면 예외).
- 브라우저로 열어 모바일 폭(약 360px)에서 가로 스크롤이 생기지 않는지 확인.
- 완성 후 사용자에게 전달. **커밋·push는 사용자가 지정한 브랜치에서만, 버전·CHANGELOG는 건드리지 않는다.**
