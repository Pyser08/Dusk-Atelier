⚠️ 제작자분들, 배포 기준 버튼은 꼭 눌러 주세요
패치는 "배포 기준"과 지금 상태의 차이만 담아요. 기준이 없거나 틀리면 패치가 비거나, 받는 사람에게 엉뚱한 내용까지 들어가요.
· 봇·모듈을 배포한 직후, 고치기 전에 개발 탭 → 대상 고르기 → [지금 상태를 기준으로 표시]를 누르세요.
· 이미 고쳐 버렸다면 [파일에서 기준 불러오기]로 배포했던 파일을 고르거나, 기록에서 고치기 전 상태를 골라 주세요.
· 패치를 만들 때 [만든 뒤 새 버전을 다음 기준으로]를 켜 두면 다음 기준이 자동으로 옮겨져요.
1📂 파일 두 개로 패치 만들기
이미 있는 봇 카드 두 개(배포한 버전, 새 버전)만으로 패치를 만들어요. 리스 안의 봇을 따로 기준으로 잡아 둘 필요가 없어요.
① 패치 만들기 열기 · 개발 탭 → 대상의 [불러오기] → [파일 두 개로 패치…], 또는 패치 만들기에서 [파일 두 개 비교]를 골라요.
② 기준 파일 · 사람들이 지금 가지고 있는 배포본(.charx·.png·.jpg / 모듈은 .risum·.json)을 골라요.
③ 새 버전 파일 · 업데이트를 마친 파일을 골라요. 바뀐 곳 목록이 바로 보여요.
④ 패치 파일 만들기 · 버전·변경 내용을 적고 누르면 .rbupatch가 받아져요. 바뀐 에셋만 담겨요.
2🧩 조립한 파일과 비교하기
리스에서 직접 고치지 않고 밖에서 조립한 경우에 써요. 대상의 [불러오기] → [조립한 봇 카드와 비교해 패치…]를 누르면, 저장해 둔 배포 기준과 그 파일을 비교해요.
· 불러온 파일은 개발 모드 안에서만 써요. 리스의 봇·모듈 목록에는 들어가지 않아요.
· 패치 만들기 화면의 ② 새 버전 칸에서 [리스 상태로 돌아가기]를 누르면 원래대로 비교해요.
· 기준과 새 버전의 이름·제작자·네임스페이스가 다르면 그래도 진행할지 먼저 물어봐요. 조립하면서 이름이 바뀐 거라면 진행하면 돼요.
3📥 로어북·정규식·트리거 불러오기
대상의 [불러오기] → [로어북·정규식·트리거 (.json)…]로 파일을 고르고, 넣을 목록과 방식을 골라요.
· 합치기: 이름·키가 같은 항목은 파일 내용으로 바꾸고, 새 항목은 뒤에 붙여요. 파일에 없는 기존 항목은 남아요.
· 전체 덮어쓰기: 고른 목록을 통째로 파일 내용으로 바꿔요.
· 리스 내보내기 파일, 모듈 .json, 카드 .json, 배열만 든 .json을 모두 알아봐요.
· 불러오기 전 상태는 자동으로 백업돼서 도구 → 기록에서 되돌릴 수 있어요.
4📤 내보내기
대상의 [내보내기]에서 지금까지 못 받던 것들을 바로 받을 수 있어요.
· 로어북·정규식·트리거 .json: 리스에서 다시 불러올 수 있는 형식이에요.
· 모듈 .json, .risum 전체
· 봇 카드 .charx: 에셋과 로어북·정규식·트리거를 그대로 담아요.
