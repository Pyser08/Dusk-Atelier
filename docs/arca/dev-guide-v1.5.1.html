개발 목록
•개발 중인 모듈·봇을 모아 두는 곳이에요. 새 모듈·새 봇을 만들거나, 있는 것을 넣고 뺄 수 있어요.
•항목마다 개발 버전을 적고, 편집·에셋으로 바로 들어가요.
•체크포인트 저장: 메모를 붙여 지금 상태를 저장해요. 도구 → 기록에 보여요.
검사
•오류 · 주의 · 참고로 나눠 문제를 보여 줘요. 편집기에서 저장할 때도 같은 검사를 해요.
테스트
•로어북 활성: 테스트 문장을 넣으면 어떤 로어북이 켜지는지 보여 줘요. 재귀 검색(켜진 항목 내용으로 다시 찾기)도 돼요.
•정규식: 입력·출력·요청·표시 중 종류를 골라 결과를 미리 봐요.
릴리스 기록
•만든 패치의 버전과 변경 내용이 쌓이고, 변경 기록을 복사할 수 있어요.
📦모듈 탭 · 캐릭터 탭의 제작 기능편집기와 에셋 관리자 — 모듈과 봇이 같은 화면을 써요
편집기
•탭: 정보 · 로어북 · 정규식 · 트리거 · JSON. 항목 추가·복제·삭제·순서 바꾸기, 로어북 폴더는 RisuAI 로어북 창과 같은 저장 형식이라 양쪽에서 그대로 보여요.
•Ctrl+F 찾기, Ctrl+S 저장, Ctrl+Z 되돌리기, Ctrl+Shift+Z 다시 하기. 항목별 스크롤·커서 위치를 기억하고, 긴 줄은 자동 줄바꿈돼요.
•코드 편집기: 정규식 IN/OUT과 트리거 Lua 칸에 문법별 색이 들어가고, 괄호를 누르면 짝 괄호도 표시돼요. CBS 사전을 누르면 고치던 칸에 바로 넣어요.
•첫 메시지는 일반/코드 모드로 고쳐요.
검사 · 저장
•정규식 문법 오류, 키가 없는 로어북(구분선용 항목은 빼고), 없는 폴더를 가리키는 항목을 저장 전에 알려 줘요.
•적용 전에 바뀐 내용을 요약해서 보여 주고, 저장 전 상태를 백업해요. 봇을 저장할 때 채팅과 메모는 건드리지 않아요.
에셋 관리자 (제작용)
•일괄 교체(이름 또는 순서로 맞춤), 이름 바꾸기, 하위 폴더 정리. 폴더 구분은 플러그인 설정에 저장하고 모듈 데이터에는 쓰지 않아요.
•메타데이터: PNG 텍스트·EXIF·XMP·WebP 정보를 보고, 그림은 두고 메타데이터만 지울 수 있어요. 배포 전에 정리할 때 좋아요.
•최적화: WebP(지원하면 AVIF)로 바꿔 파일 크기를 줄여요. 미리 계산해서 더 작아지는 것만 바꿔요.
•중복 찾기: 내용이 같은 에셋을 묶어 보여 주고 체크한 이름만 빼요. 묶음마다 하나는 남겨요.
🎯로어북 규칙 (실험)로어북 항목마다 켜질 조건을 정하기 — 봇·모듈 편집 → 로어북 → 항목 맨 아래
어떻게 돌아가나요
•규칙을 켜면 항목 내용이 @@activate + {{#if 변수}}로 감싸져요. 입력하는 순간(프롬프트 조립 전) Dusk가 규칙을 계산해 변수를 켜고 끄고, 그다음 CBS·변수·#if·배치·토큰 계산은 리스가 평소대로 해요.
•규칙은 항목 안에 저장돼 .charx·PNG·.risum으로 내보내도 따라가요. Dusk가 없는 사람에게는 꺼진 항목으로 보여요.
•캐릭터·모듈 로어북 모두 돼요. 추가 권한은 필요 없어요.
언제 켜질까 (조건)
•키가 최근 대화에 있음(키 중 하나만 맞아도) · 특정 단어 있음 · 특정 단어 없음 · 채팅 변수 비교 · 턴 범위 · 단어 누적 N번 이상 · 항목이 N번 이상 켜짐 · 다른 항목이 이번 턴에 켜짐/안 켜짐
•모두 만족 / 하나라도 만족, 찾는 범위(최근 N개 메시지)
•이름 경계: '김민'이 '김민수'엔 안 걸리고 '김민이·김민에게'엔 걸려요.
얼마나 자주 · 같이 켜기 · 어디에 넣을까
•켜질 확률, 반복(제한 없음 / 채팅에서 한 번 / N턴 쉬기), 중복 금지 그룹(같은 그룹은 한 턴에 하나만), 유지(켜지면 N턴 동안 계속 켜 둠)
•같이 켜기: 이 항목이 켜지면 다른 항목도 N% 확률로 켜요. 대상 항목도 규칙을 켜 두세요.
•넣을 위치(로어북 자리 / 대화 끝에서 N개 위 / 대화 맨 끝)와 역할
누적 · 유지 · 켜질 때 변수
•단어 누적 N번 이상: 대화 전체에서 그 단어가 나온 메시지 수(사용자 말/봇 말 구분 가능). 항목이 N번 이상 켜짐: 그 항목이 지금까지 켜진 턴 수(최근 50번).
•유지: 한 번 켜지면 N턴 동안(켜진 턴 포함) 조건·확률 없이 계속 켜 둬요. 유지 중에 조건이 또 맞으면 다시 N턴부터 세요.
•켜질 때 변수: 새로 켜질 때 채팅 변수를 정하기 · 더하기 · 빼기 · 곱하기 · 나누기 · 수식으로 바꿔요. 유지로 이어진 턴에는 바꾸지 않아요. 다른 규칙의 변수 비교 조건이나 본문의 {{getvar::이름}}과 이어져요.
•한 번 맞으면 계속 맞는 조건(단어 누적 등)은 매 턴 켜져요. 한 번만 켜려면 반복을 "채팅에서 한 번"이나 "쉬었다가"로 같이 걸어요.
변수 수식
•연산을 수식으로 고르면 입력칸 옆 ? 쓰는 법 버튼에서 부호와 함수 설명을 볼 수 있어요.
•부호 + - * / % ^ ( ), 함수 min max abs floor ceil round clamp rand, 지금 턴 turn(또는 턴). 변수 이름은 그대로 쓰고, 숫자가 아니거나 없으면 0이에요.
•예) clamp(love*1.5, 0, 100) · max(hp - 10, 0) · floor(hp / 2) · rand(1, 6)
•0으로 나누거나 수식이 틀리면 그 항목만 건너뛰고 값은 그대로 둬요. 틀린 부분은 입력칸 아래에 빨갛게 알려 줘요.
•리롤하면 변수도 리롤된 결과 기준으로 다시 맞춰지고, 리롤하지 않으면 원래 결과로 돌아가요(Lua·CBS가 직접 바꾼 값은 건드리지 않아요).
규칙 시험 (가상 대화)
•봇·모듈 편집 화면 우측 하단 [규칙 시험] 버튼을 누르면 창이 펼쳐져요. 어느 탭에서나 보이고, 창이 떠 있어도 뒤쪽 편집 화면을 쓸 수 있어요.
•입력을 한 턴씩 보내면 켜진 항목과 이유, 변수 변화가 나와요. 안 켜진 항목은 [왜?]에서 안 맞은 조건과 지금 값, 확률 실패, 쿨다운, 그룹 충돌을 보여 줘요.
•[시험 환경]에서 지금 턴, 현재 변수, 이전 대화, 항목별 켜진 기록, 확률 고정(그대로 / 모두 켜짐 / 모두 안 켜짐)을 정해 모든 조건을 시험해요. 봇 답변도 넣을 수 있어요.
•저장 전 편집 내용 그대로 계산하고 실제 채팅과 변수는 건드리지 않아요. [마지막 턴 취소], [처음부터]가 있어요.
알아 둘 것
•본문은 {{#if}}와 {{/if}} 사이만 고치세요. 바깥 줄은 저장할 때 자동으로 맞춰져요.
•키가 없는 항목은 저장할 때 자동으로 항상 켜짐이 돼요(리스가 키 없는 항목을 건너뛰기 때문). 방식은 일반으로 두고, 하위 방식에는 켜지 마세요.
•채팅 중엔 도구 → 로어북 로그나 응답 아래 [📖 로어북] 버튼으로 무엇이 들어갔는지 봐요. F12 콘솔의 [Dusk 규칙] 줄도 있어요.
이렇게 써요 (예시)
•호감도: 칭찬 항목에 켜질 때 변수 love 더하기 5. 고백 항목에는 조건 "변수 love > 49" + 반복 "채팅에서 한 번".
•날씨: 맑음·비·눈 항목에 같은 중복 금지 그룹 이름(예: weather)을 줘요. 한 턴에 하나만 켜져요.
•사과가 세 번 나오면: 조건 "단어 누적 3번 이상(사과)" + 반복 "채팅에서 한 번". 한 번 맞으면 계속 맞는 조건이라 반복을 같이 걸어야 해요.
•한 번 켜지면 5턴 동안: 유지를 5로 둬요. 유지 중에는 조건·확률을 다시 보지 않아요.
•NPC가 수백 명인 봇: 인물마다 키 + 이름 경계 + 규칙을 켜 두면 그 장면에 나온 인물만 들어가서 토큰이 줄어요. 시험은 우측 하단 [규칙 시험]으로 해요.
📤업데이트 패치 만들기수정한 부분만 담은 .rbupatch 배포
세 단계
•① 배포 기준: 배포한 상태 그대로일 때 '지금 상태를 기준으로 표시'를 눌러요. 이미 고쳤다면 기록에서 수정 전 상태를 골라요.
•② 바뀐 내용: 정보·로어북·정규식·트리거·에셋 중 바뀐 곳을 수정/추가/삭제로 보여 주고, 패치 크기를 미리 알려 줘요.
•③ 패치 정보: 버전·제작자·변경 내용을 적고 '패치 파일 만들기'를 누르면 이름_v버전.rbupatch가 받아져요.
만든 뒤
•지금 상태를 새 기준으로 옮기면, 다음 패치에는 그 뒤에 고친 것만 들어가요.
•도구 탭, 모듈 메뉴, 봇 상세, 개발 탭에서 열 수 있어요.
내 수정만 내보내기 · 패치 적용
•제작자 원본과 비교해 내가 바꾼 부분만 파일로 저장해요. 바뀐 필드와 항목만 담아서 작아요. 예: 276MB 모듈에서 로어 5개 수정 → 약 20KB. 바꾼 에셋도 함께 넣을 수 있어요.
•받는 쪽은 모듈 메뉴 또는 봇 메뉴의 패치 적용에서 .rbupatch를 골라요. 적용 전에 버전과 변경 내용을 보여 주고, 받는 사람이 직접 고친 부분은 그대로 남아요.
🧰도구 탭 (제작자용)만들면서 확인하고 되돌리는 도구
로어북 로그 — 디버깅
•응답마다 어떤 항목이 왜 들어갔는지(출처·키 일치/항상 켜짐/Dusk 규칙)를 기록해요. 보낸 프롬프트를 직접 확인하고, 못 보는 환경에서는 키·규칙으로 추정한다고 기록에 적어요.
•응답 아래 📖 로어북 N개 버튼으로 채팅 중에 바로 봐요. 설정 탭에서 로그 끄기·버튼 숨기기가 돼요. 최근 300개까지 남겨요.
기록 · 업데이트 가져오기
•개발 탭의 체크포인트와 편집·업데이트 전 상태가 기록에 쌓여요. 되돌리기 전에 지금 상태도 먼저 백업하고, 모듈은 그 시점과 비교해 봐요.
•업데이트 가져오기는 지난번 받은 것 · 지금 · 새 버전을 3방향 병합해요. 내 버전을 새 파일로 받아도 사용자가 고친 부분은 지켜져요.
.risum 인스펙터 · 전체 백업
•모듈 파일 안의 필드별 크기, 압축률, 에셋 목록을 보고 ZIP으로 풀어요. 파일이 왜 큰지 볼 때 써요.
•에셋까지 백업은 에셋 파일도 모두 담아 다른 서버로 옮길 때 써요.
🧪플러그인 탭의 개발용 기능만들기 · 저장소

🔗DA Interop — 플러그인 연동여러분의 플러그인 설정을 Dusk 연동 설정 화면에 띄우기
링크
•스니펫 생성기: 플러그인 정보와 설정 항목을 넣으면 코드를 만들어 줘요.
•저장소 · 명세 · 예제 플러그인
•Dusk 플러그인 탭의 만들기에서도 같은 코드로 시작할 수 있어요.
붙이는 순서
•스니펫은 플러그인 맨 위에, registerInterop({...})은 맨 아래에 둬요. 등록은 스니펫보다 뒤에 있어야 동작해요.
•apply 안에 받은 값을 반영하고 플러그인이 직접 저장하는 코드를 채워요. 같은 패치는 한 번만 전달돼요.
•getValues는 지금 값을 돌려주고, 플러그인 쪽에서 값이 바뀌면 refresh()를 불러 주세요.
// 1) 생성기에서 받은 스니펫을 플러그인 맨 위(머리말 아래)에 붙여요
// 2) 플러그인 본문
const risu = globalThis.risuai ?? globalThis.Risuai;
const KEY = 'my_plugin:settings'; // 저장 키는 '플러그인이름:'으로 시작
let settings = { enabled: true, tone: 'soft', strength: 0.5 };

// 3) 맨 아래에 등록 코드
const handle = registerInterop({
  id: 'my-plugin', // 소문자·숫자·.-_ (2~64자)
  name: '말투 바꾸기',
  version: '1.0.0',
  pluginName: 'my_plugin', // //@name 과 같게
  fields: [
    { key: 'enabled', label: '켜기', type: 'toggle', default: true },
    { key: 'tone', label: '말투', type: 'select', options: [
      { value: 'soft', label: '부드럽게' }, { value: 'dry', label: '건조하게' } ] },
    { key: 'strength', label: '세기', type: 'slider', min: 0, max: 1, step: 0.1 }
  ],
  presets: [{ name: '기본', values: { enabled: true, tone: 'soft', strength: 0.5 } }],
  getValues: () => settings, // 지금 값을 돌려줘요
  apply: async (values, ctx) => { // Dusk에서 보낸 값
    settings = { ...settings, ...values };
    await risu.pluginStorage.setItem(KEY, JSON.stringify(settings)); // 직접 저장
  }
});
// 플러그인 쪽에서 값이 바뀌면: handle.refresh()
toggle켜기·끄기
number숫자 칸 (min·max·step)
slider슬라이더 (min·max·step)
select고르기 — options: [{ value, label }]
text / textarea한 줄 / 여러 줄 글
color색 고르기
공통 속성key · label · type · default · description · group
동작 방식
•플러그인이 da_interop:reg:<id>에 자기 정보·항목·지금 값을 올려요.
•Dusk가 da_interop:patch:<id>에 바꿀 값과 번호(rev)를 써요.
•플러그인은 화면이 보일 때 3초마다 확인하고, 새 번호면 apply 후 적용 번호와 오류를 다시 올려요. Dusk는 이걸 보고 적용됐는지 알려 줘요.
•모두 공식 pluginStorage만 써요. 샌드박스를 우회하지 않아요.
•플러그인 자체 설정 키에도 플러그인이름: 같은 접두어를 붙여 다른 플러그인과 겹치지 않게 해 주세요.
📜플러그인 머리말 주의설치가 안 되거나 버전이 0으로 읽힐 때
머리말
•//@name //@display-name //@api 3.0 //@version //@update-url
•//@version은 0.0.1 이상이어야 하고 파일 앞 512바이트 안에 있어야 해요. //@update-url을 쓰면 버전이 꼭 필요하고, 주소는 https만 돼요.
•RisuAI는 파일 전체에서 마지막으로 나온 //@ 줄을 읽어요. 코드 안 문자열이라도 줄 맨 앞이 //@version이면 그 값으로 덮여요. 템플릿 문자열에 머리말을 넣을 땐 줄 맨 앞에 오지 않게 이어 붙이세요.
