# 프로바이더 보완 계획 — Yumi Provider Manager v1.19.3 참고 (2026-11-06)

## 원칙
- 지금 Dusk 프로바이더(공급자 14종·키 순환·대체 사슬·캐시·도구·번역기·예산)를 **보완**한다. 새로 갈아엎지 않는다.
- Provider Manager(PM)는 **원작자 허락을 받음**(2026-11-06 사용자 확인) → 참고하거나 일부 코드를 가져와도 된다. 가져온 파일은 머리 주석에 “Yumi Provider Manager v1.19.3에서 가져옴/참고” 출처를 적고, NOTICE.md에 고지함. 받은 원본 파일 자체는 저장소에 넣지 않는다(참고용은 작업 폴더에만).
- 화면은 Dusk 방식(kit.js, UI-STYLE.md). 애드온 `addons/provider`(hooks:true) 안에서만 바뀐다 → 고칠 때 애드온만 배포.
- 각 단계: 실패 시험 → 구현 → npm test·build·check·e2e(run-provider) → 애드온 버전 올려 배포.

## PM에 있고 Dusk에 없던 것 → 단계
| 단계 | 기능 | Dusk에 넣는 방식 |
|---|---|---|
| 1 ✅ | 진행 창 | `engine/provider/board.js`(요청 ID별 상태, 끝난 카드만 5초 뒤 닫힘, 진행 중이 없을 때만 숨김) + `data/provider/progress.js`(리스 화면 창 하나, 만드는 중 Promise 공유·실패 시 비움, 끄면 창만 치움). PM의 동시 요청 덮어쓰기·조기 숨김·창 두 개 버그를 구조로 막음. 설정: 용도 탭 ‘진행 창 보이기’. |
| 2 ✅ | 재시도·키 회전 보강 | 키 모드에 ‘실패한 뒤에만 다음 키(on-error)’ 추가, 재시도 대상(429만 / 429+5xx) 고르기, 재시도 오류를 하나씩 기록. |
| 3 ✅ | 사용량 통계 | 모델별·날짜별 요청·토큰·비용·캐시(읽기·쓰기 5분/1시간·절감액) 표, 기간(오늘·7일·30일). 요청 내용은 저장 안 함. |
| 4 ✅ | 로그 보기 | 최근 요청·오류 기록(키 가림), 보관 개수, 복사. 진행 창 카드에서 바로 열기. |
| 5 ✅ | 공급자 추가 | AWS Bedrock(IAM 키·Bearer), NovelAI, OpenCode, Gemini Express Mode. 잔액 조회 전용 토큰 칸. |
| 6 ✅ | 출력 표시 | 실시간 글자 수/토큰 추정(진행 창), 추론 과정 생략·요약 보기, PDF 해상도. |
| 7 ✅ | 캐시 고급 | 격자 캐시 포인트(긴 대화에 고정 지점), 캐시 학습(반복되는 앞부분 자동 표시). |
| 8 ✅(Anthropic) | 배치 API | Anthropic·OpenAI 배치: 끝날 때까지 기다리기 / 만들고 끝내기, 같은 입력 재요청은 새 배치 안 만듦. Cellar가 있으면 서버가 기다림. |
| 9 ✅ | 라우터 | 조건(글자 수 이상·이하, 글자 포함, 용도)으로 프로필 고르기 — 지금의 용도·봇별 프로필 위에 규칙 한 겹. |
| 10 ✅ | 도구 확장 | MCP(sse·streamable-http) 서버 연결, 훅(모델별 요청 전·후 처리). 쓰기 도구는 기본 끔+확인. |
| 11 ✅ | 다른 플러그인 창구(IPC) | pluginStorage 우편함 방식: 요청 키 `dusk.ipc.v1.req.<플러그인>`(그 플러그인만 씀) → Dusk가 처리 → 결과 키 `dusk.ipc.v1.res.<플러그인>`(Dusk만 씀). 기본 꺼짐, 처음 보는 플러그인은 허용 여부를 묻고 저장. 동시 처리 수 제한, 재시도·대체 사슬은 runner가 그대로 적용. 규칙 docs/IPC-provider.md. |

## 순서 제안
1~4(쓰기 편함·문제 파악) → 5(공급자) → 6~7 → 8~11. 단계마다 CHANGELOG·안내서(provider) 갱신.
