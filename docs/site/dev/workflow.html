작업 흐름과 파일 찾기

고칠 때의 순서와, 작업별로 어떤 파일부터 읽으면 되는지 모았어요.

작업 루프

  1. 소스 수정 → 테스트npm test로 확인해요. 테스트는 tests/<이름>.test.js에 있어요.
  2. 빌드와 확인npm run build로 dusk_atelier.js를 다시 만들고, npm run check가 "동일함"인지 봐요. 빌드물도 함께 커밋해요.
  3. UI를 건드렸다면node tests/e2e/run-smoke.mjs로 연기 시험을 해요.
  4. 구조가 바뀌었다면node tools/source-map.mjs > docs/source-map.md로 소스 지도를 다시 만들어요.
💡
Node 22 기준이에요. 3.6MB가 넘는 빌드물 dusk_atelier.js는 읽지 말고 src/를 보세요.

지켜야 할 규칙

  • 계층: engine/은 순수 로직, data/는 api·저장소, ui/는 화면, tide/는 RisuTide예요.
  • 자동 생성 폴더: src/engine/pot/, src/data/pot/는 직접 고치지 않아요.
  • UI: 부분 갱신을 우선해요(전체 재렌더는 버벅임 원인). DOM은 ui/dom.js의 h()/replace(), 공용 위젯은 ui/kit.js를 써요.
  • 데이터: 장기 기억 저장 데이터는 사용자 기기에 이미 쌓여 있으니, 식별자·스키마를 바꾸면 예전 데이터 마이그레이션과 테스트를 함께 만들어요.
  • 원본 보호: 원본 봇·채팅은 수정하지 않고 새 객체만 만들어요.
