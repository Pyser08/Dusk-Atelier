호스트 호환 규칙

같은 dusk_atelier.js 하나로 RisuAI · RisuBard · PocketRisu에서 돌게 하는 규칙이에요.

원칙

호스트별 빌드를 만들지 않아요. 차이는 전부 실행 중 기능 감지로 흡수해요. 호스트 이름으로 분기하지 말고 "그 기능이 있는가"로 분기해요.

호스트 구분 신호

신호의미
api.getRuntimeInfo?.() → platform === "node"PocketRisu·RisuBard(서버형)
api.bardWiki?.getDocuments 함수 존재RisuBard의 BardWiki 사용 가능
globalThis.__RBM_ENTRY__ === "legacy"구형 진입(간이 UI만 등록)
호스트가 저장을 막는 오류 문구(still loading, not loaded, history is only partially)RisuVault 등 채팅 보호 — 한국어 오류로 바꿔 보여 줘요

API 사용 원칙

1. 플러그인 형식
머리말은 tools/build.mjs의 banner가 만들어요: //@name dusk_atelier, //@api 3.0, //@version, //@update-url. //@name을 바꾸면 사용자 저장소(pluginStorage)와 업데이트가 끊겨요. 본문은 IIFE 한 덩어리이고, 소스 중간에 //@ 줄이 있으면 빌드가 실패해요(의도된 검사). 진입은 src/main.js의 start()예요.
2. 선택적 API는 옵셔널 호출 + catch
api.getRuntimeInfo?.(), api.getRootDocument?.().catch(() => null), api.bardWiki?.…처럼 써요. 없으면 기능을 끄거나 대체 경로로 가요.
3. 훅 등록은 try/catch
실패해도 앱 전체는 계속 떠야 해요. 실패는 console.log("[Dusk Atelier] …")로만 남겨요.
4. 훅 안에서 오래 붙잡지 않기
output/display 훅은 디바운스 후 비동기로 처리해요. 응답 렌더를 막으면 호스트 전체가 멈춰요.
5. 주입은 요청 사본에만
beforeRequest replacer로 요청 사본에만 넣어요. 저장된 채팅·봇 데이터는 건드리지 않아요.
6. 저장 쓰기는 래퍼로
setCharacterToIndex·setDatabaseLite는 main.js의 래퍼를 거쳐요(호스트 차단 오류 처리). setDatabase 전체 저장은 피해요(서버형 호스트에서 느리고 충돌 위험).
7. 네트워크
플러그인 창은 CSP로 fetch가 막힐 수 있어요. api.nativeFetch(url, { method: "GET" })를 먼저 쓰고(method를 생략하면 POST로 가서 실패해요), 실패하면 일반 fetch로 가요.
8. 리스 화면 DOM
api.getRootDocument()는 비동기 래퍼예요. 모든 querySelector 앞에 await를 붙여요. 셀렉터는 RisuAI·Pocket 둘 다 고려해요.
9. 캐릭터 추가 후 순서
Pocket·Bard는 checkCharOrder 반영이 늦거나 빨라서 ensureCharacterInOrder(engine/character.js)를 다시 써요.

기억 백엔드

  • local: 플러그인이 분석·저장·주입해요(기본).
  • bardwiki: RisuBard 위키 읽기 + 등급 쓰기만 해요(중복 방지). 설정을 바꾼 뒤에는 새로고침이 필요해요(훅 재등록).
  • 둘 다 켜면 중복이라 화면이 경고해요.
