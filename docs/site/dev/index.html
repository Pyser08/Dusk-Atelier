개발자

개발자 가이드

모듈·봇 제작자는 패치 배포를, 플러그인 개발자는 연동과 빌드를 여기서 찾아요.

개발자 모드

도구 탭 맨 위 스위치로 켜요. 수정한 부분만 담은 업데이트 패치를 쉽게 만들어 배포할 수 있어요.

패치(.rbupatch) 만들기

도구 탭, 모듈 메뉴, 봇 상세에서 열어요.

  1. 배포한 버전(기준)배포한 상태 그대로일 때 "지금 상태를 기준으로 표시"를 눌러요. 이미 고쳤다면 기록에서 수정 전 상태를 고를 수 있어요.
  2. 바뀐 내용기준과 비교해 정보·로어북·정규식·트리거·에셋 중 바뀐 곳을 수정/추가/삭제로 보여 주고, 패치 크기를 미리 알려 줘요.
  3. 패치 정보버전, 제작자, 변경 내용을 적고 "패치 파일 만들기"를 누르면 이름_v버전.rbupatch가 내려받아져요.

만든 뒤 지금 상태를 새 기준으로 옮길 수 있어요. 그러면 다음 패치에는 그 뒤에 고친 것만 들어가요.

📦
바뀐 필드와 바뀐 목록 항목만 담아서 대형 봇·모듈도 패치가 작아요. 예: 276MB 모듈에서 로어 5개 수정 → 약 20KB.

받는 사람 쪽

"패치 적용"으로 파일을 골라요. 적용 전에 버전과 변경 내용을 보여 주고, 받는 사람이 직접 고친 부분은 그대로 남아요.

DA Interop

DA Interop 코드를 넣은 플러그인은 플러그인 탭에 설정 화면이 자동으로 생겨요. 값·프리셋을 보내면 그 플러그인이 적용하고 결과를 알려 줘요. 연동 코드가 든 템플릿은 플러그인 탭의 "만들기"에서 고치고, 검사·내려받기·설치까지 할 수 있어요.

⚠️
RisuAI(PR #1572 이후)와 이를 따르는 포크는 플러그인이 다른 플러그인을 켜고 끄거나 순서·코드를 바꾸는 것을 막아요. 그런 기능은 없어요.

빌드와 검사

npm install                    # esbuild 설치
node tools/build.mjs           # src/ → dusk_atelier.js (버전은 package.json)
node tools/build.mjs --check   # 빌드 결과가 저장소의 dusk_atelier.js와 같은지 확인

테스트는 npm test, 빌드와 확인은 npm run build → npm run check("동일함")예요. 빌드물도 함께 커밋해요.

소스 구조

폴더내용
src/engine/파일 읽기·쓰기(risum·charx·png·jpeg·zip), 매칭, 3방향 병합, 업로드, 백업, 패치, 이미지 도구
src/data/모듈·프리셋·페르소나·캐릭터 순서 저장
src/ui/테마, 공용 부품, 화면(screens/), 가져오기 화면(legacy.js)
src/tide/RisuTide에서 가져온 업데이트 판단 로직

src/engine/pot/, src/data/pot/는 tools/pot-split.mjs가 자동 생성하니 직접 고치지 않아요.

저장 위치

모듈 데이터에는 RisuAI 표준 필드만 쓰고, 순서·폴더·꺼짐 같은 관리 정보는 전용 키에 둬요. 설정은 pluginStorage에 저장돼서 다른 기기와 동기화돼요.

키내용
rbm:ui:v1테마, 백업 보관 수, 개발자 모드
rbm:moduleMeta:v1모듈 목록 폴더, 이름 색, 에셋 폴더, 연결 기억
rbm:disabledModules:v1꺼 둔 모듈 보관함
rbm:moduleOrder:v1모듈 순서
rbm:personaInjected:v1페르소나 연결로 넣은 기록
rbm:presets:v1프리셋
rbm:persona:v1페르소나 연결
rbu:index:v1원본 기록, 백업 목록
