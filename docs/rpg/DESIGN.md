# Dusk Saga — Dusk RPG 애드온 설계 v1

기반: Risu Tactics v0.9.36 (원작자 허락, 프로젝트 인수로 간주)
형태: Dusk Atelier **별도 애드온** (`addons/rpg/`, 카테고리 game 신설)
상태: P0 엔진 이식 완료, 저장·화면 이식 대기 (브랜치 Dusk-RPG)

---

## 1. 목표
Risu Tactics(FE식 그리드 전투 + RP 연동)를 Dusk 안으로 옮기고, 네 갈래로 키운다.
1. **전투 심화** — 클래스·상태이상·목표·AI가 더 깊은 전술전
2. **RPG 루프** — 전투 밖 진행(골드·상점·퀘스트·거점·월드맵)
3. **RP 연동** — 장기기억(인물·관계·상태)과 전투가 서로 주고받음
4. **화려한 UI·연출** — 글래스 UI, FE식 전투 컷씬, 컷인, 날씨·이펙트

원칙: AI 호출은 늘리지 않는다(생성 1회 기본), 모든 AI 작업은 '생성 중지'에 잡힌다, RisuAI·RisuBard·PocketRisu 공통 동작.

## 2. 현재 Risu Tactics 분석 요약
**좋은 점(그대로 살림)**
- 엔진(RT)이 DOM·api 없이 순수 함수 → Dusk `engine` 계층 규칙과 맞음, 테스트 쉬움
- 시드 RNG(mulberry32) + 이벤트 배열 재생 구조 → 결정적 재현·되감기(천각의 박동)가 가능
- 모델 출력 정규화(clamp, tame) → 이상한 JSON에도 전투가 안 깨짐
- 스킬 3층(common/faction/own), 프리셋 적, 맵 프리셋 + 좌우/상하 반전 변형
- 결과를 user 메시지 블록으로 넣고 오래된 블록은 beforeRequest에서 지움 → 토큰 관리 잘됨

**고칠 점**
- 2,150줄 단일 파일, UI 상태(V)·전역 S가 얽힘 → 모듈 분리 필요
- 저장이 채팅당 JSON 통째(start 스냅샷·hist 40개 포함) → 커질수록 느림. 박동 기록은 diff/시드 재생으로 줄일 것
- `reach()`가 선형 큐 다익스트라(O(n²)) — 맵 20×16 한도에선 괜찮지만 위험 범위·AI 탐색에 반복 호출됨 → 이진 힙 + 턴 내 캐시
- UI 1629줄: `else if (u && V.stage === 'target') { } else if (같은 조건)` 빈 분기 중복(동작엔 영향 없음, 정리 대상)
- AI 호출이 `runLLMModel` 직접 → Dusk에선 `ctx.dusk.ai.run`/`runAITask`로 바꿔 중지 버튼 연결
- 저장 키 `rt2:*`는 Risu Tactics 플러그인 저장소라 Dusk에서 직접 못 읽음 → 기존 '저장 내보내기' JSON 가져오기로 이전

## 3. 구조 (Dusk 계층에 맞춤)
```

  board.js      지형·이동(힙 다익스트라)·위협 범위·시야
  combat.js     forecast·resolve·strike·방진/공진
  status.js     상태이상 (신규)
  ai.js         적 AI 성격 (확장)
  phase.js      턴·증원·목표 판정
  growth.js     레벨업·전직·성장 보정
  econ.js       골드·상점·보상 (신규)
  normalize.js  LLM 출력 정규화(normUnit/normSkill/normWeapon)
  prompts.js    생성·성장·재생성 프롬프트
  digest.js     서술용 기록 요약
src/rpg/data/     저장(채팅별 키 + 공용 보관함), 결과 스테이징, memoryApi 연결
src/rpg/ui/       화면(전장·컷씬·편집기·메뉴), 연출
```

- 저장 형식 `v: 3`, v2(Tactics) 가져오기 마이그레이션 + 테스트

## 4. 기능 로드맵

### P0 — 이식·동등성 (먼저)
- RT 엔진을 위 모듈로 쪼개 옮김, 같은 시드·같은 입력 → 같은 로그가 나오는 **동등성 테스트**(데모 전장 자동 플레이 기록 비교)
- 기존 기능 전부 유지: 생성/시간 지난 뒤 생성, 성장 반영, 재생성, 편집기, 보관함, 저장 전장, 박동, 엑스컴 규칙, 결과 카드
- Tactics 저장 JSON 가져오기

### P1 — 전투 심화
- **클래스·전직 트리**: 하급→상급(Lv 21) 분기 2갈래, 전직 시 스탯 보너스·무기 해금·이동 유형 변경(기병→팔라딘 등)
- **상태이상**: 독·화상(턴 피해), 기절(행동 불가), 속박(이동 불가), 침묵(기술 불가), 버프/디버프(턴 수) — 스킬 flags에 `inflict` 추가
- **목표 확장**: 호위(NPC 생존+도착), 탈출(지정 칸), 방어(N턴 거점), 포획(HP 0 대신 사로잡기), 다단계(1페이즈 승리 후 맵 이어짐)
- **지형 이벤트**: 불붙는 숲, 무너지는 다리, 열리는 문, 함정 칸(숨김)
- **시야(전장의 안개)** 옵션
- **AI 성격**: 돌격·신중(HP 낮으면 후퇴)·사냥꾼(약한 대상 집중)·호위·보스 패턴(N턴마다 광역기)
- **지원(서포트)**: 인접 아군의 관계도 수치에 따라 명중·회피 보너스 (P3와 연결)
- 대형 유닛(2×2 보스) — 후순위

### P2 — RPG 루프
- **골드·보상**: 전투 승리·퀘스트로 획득, 적 드롭
- **상점·대장간**: 구매/판매, 무기 강화(+1~+5), 이름 붙이기
- **수송대**: 파티 공용 창고(개인 소지 5칸 유지)
- **퀘스트 보드**: RP 흐름에서 뽑은 의뢰(전투 생성 호출에 한 번에 같이 받음 — 추가 호출 없음)
- **거점(캠프)**: 휴식·지원 대화 트리거·훈련(경험치 소량)
- **월드맵**: 노드형(장소 간 이동, 일부 노드는 전투), 장소는 로어북/RP에서
- 난이도: 쉬움/보통/어려움 + 영구 사망(클래식) 옵션

### P3 — RP 연동 (장기기억 애드온 `memoryApi`)
- 장기기억 인물 → 유닛 시트 자동 제안(이름·이미지·관계)
- 관계·호감도 → 서포트 보너스, 연애/라이벌 관계 → 공진 연출
- 장기기억 **상태이상·몸 흔적** ↔ 전투 상태 (부상 입고 끝나면 기록에 남김, 선택)
- 장기기억 **날씨 엔진** → 전투 날씨(비=활 명중↓, 눈=이동↓)
- 전투 결과를 장기기억 사건으로 기록(격파·부상·활약)
- 인물 속마음 애드온이 켜져 있으면 전투 중 결정적 순간 속마음 한 줄(AI 호출 없이 기존 출력 재사용)
- 장기기억이 없으면 지금 Tactics처럼 단독 동작

### P4 — UI·연출 (UI-GLASS 기준)
- **글래스 UI**: 빛 번진 배경 + 반투명 카드, 상단 바·측면 카드·명령 메뉴 재디자인, 모바일 390 우선
- **전투 컷씬**: 공격 확정 시 FE식 좌우 분할 화면 — 초상(봇 에셋) 슬라이드 인, HP 바 감소, 필살 시 컷인(초상 확대+대사 한 줄), 끄기/건너뛰기/빠르게 옵션
- **맵 연출**: 페이즈 배너 개편, 카메라 팬·줌(이동·공격 대상 따라감), 이동 궤적, 피격 흔들림, 격파 파편
- **이펙트 층**: canvas 하나로 파티클(마법 속성별·날씨·불·물보라) — DOM 유닛 위에 겹침, 저사양이면 자동 감소
- **레벨업 화면**: 스탯 하나씩 올라가는 FE식 연출
- **지형 그래픽**: 이모지 장식 → SVG 타일 세트(입체/평면 둘 다), 벽 높이 표현 개선
- 사운드는 선택(기본 꺼짐) — 리스 환경 자동재생 제약 확인 필요

## 5. 성능·호환
- 연출은 CSS transform/opacity만, 이펙트는 canvas 한 장 → 모바일 프레임 유지
- 박동 기록: 매 시점 보드 전체 JSON 대신 (시드 + 행동 목록) 재생 방식 → 저장 크기 대폭 축소
- 저장은 디바운스 + 채팅 전환 시 flush (Tactics 방식 유지)
- Risu 권한 대화상자(가림 문제) 처리 로직 유지

## 6. 확정 사항 (2026-11-25)
1. 이름: **Dusk Saga** (가칭 확정, 애드온 id `rpg`)
2. 영구 사망: 기본 **꺼짐** (옵션으로 켤 수 있음)
3. 컷씬: 기본 **켜짐**, 방해되지 않게 **짧게**(공격 1회 약 0.8초 이내, 필살 컷인만 조금 길게), 탭하면 즉시 건너뜀
4. RPG 루프 범위: **전투 위주** — 월드맵·거점·퀘스트 보드는 하지 않음. P2는 전투 보상(골드·드롭)·상점·강화·수송대 정도로 축소, 후순위
5. 크레딧: 스페셜 땡스에 **Risu Tactics 플러그인** 표기 (+ 애드온 설명에 "Risu Tactics 기반")
6. 작업 브랜치: **`Dusk-RPG`** (main에서 분기, 만들 때 HandOff/README.md 표 갱신)
7. 진행 방식: **화면·연출 작업은 미리보기(목업)를 먼저 보여 주고 확인받은 뒤 구현** — 모바일 390 + PC 1280 나란히

## 7. 진행 순서 제안
P0(이식·테스트) → P4 일부(글래스 UI 골격·컷씬, 미리보기 확인 후) → P1 → P3 → P2(축소판).
연출을 앞당기는 이유: 화면 구조가 먼저 정해져야 이후 기능 UI를 다시 안 만듦.
각 단계 끝마다 addons 배포로 직접 시험.
